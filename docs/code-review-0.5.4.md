# 0.5.4 项目审核与优化

本次由主代理与三个分区 agent 完成审核、实施和交叉检查。标准：抽象、复用、解耦、简洁、低嵌套、低侵入。基线为 `71eca94`；原有 18 项测试和类型检查先确认通过。

## 审核覆盖

| 分区 | 审核范围 | 处理方式 |
| --- | --- | --- |
| 引擎 | 四个适配器、公共契约、RPC、工具包装、进程清理 | 复用 JSONL 与审批；保留各协议和执行循环独立 |
| 界面 | 会话、输入、设置、模型、MCP、子代理、问答、项目、图片、大纲 | 抽纯事件/分组转换和独立组件；保持样式与发送队列策略 |
| 后台服务 | 存储、服务商、MCP、桥接、子代理、网关、网络、更新、项目/仓库、扩展与 MCP 工具包 | 优先修复并发与生命周期问题；稳定路由/算法不机械重写 |
| 主进程及发布 | 引擎编排、IPC、配置、共享类型、preload、脚本、构建/发布、文档 | 拆命令与压缩策略，统一持久化及事件订阅，补 Electron 集成验证 |

## 评估与已实施优化

| 优先级 | 证据与问题 | 优化及验证边界 |
| --- | --- | --- |
| P1 | pi 的旧 stdout/stderr 和 MCP 上游退出事件可污染新进程 | 每个进程独立解码并检查身份；覆盖重启、单块输出中途切换、断管与挂起请求 |
| P1 | 固定 `.tmp` 与独立 read-modify-write 会覆盖并发更新 | `storage.ts` 统一按文件串行、原子替换、完整读改写事务；Session/Project/Transcript 等复用 |
| P1 | 关闭提问 HTTP 客户端后 pending 不释放，子代理调用未传取消信号 | 问答与长轮询在响应关闭时清理；MCP signal 传到桥接；保留问答无超时 |
| P1 | 网页抓取只检查首个 URL，自动跳转可进入本机地址 | 每次重定向前重新检查协议和地址，并限制跳转次数 |
| P1 | Prophey 默认压缩 50%，状态/界面却显示 90%；小 token 阈值被整数百分比归零 | 统一压缩策略与有限数校验，保留小数百分比，隔离旧引擎的异步同步结果 |
| P1 | 空 Prophey 会话记录了不存在的恢复路径 | 只记录已持久化的文件会话；真实 Electron 切换发现并复测 |
| P2 | App 混合消息转换与 IPC；原生字符串历史丢内容 | 纯 `conversation-events`，独立测试流式、历史、工具结果、图片与系统通知 |
| P2 | 文件提及正则错误，项目过滤仅在文件夹模式生效 | 独立提及/分组函数；三种分组、项目根、空组及路径回归 |
| P2 | 保存失败仍关闭草稿；登录/菜单/子代理状态重复 | `runAction`、`LoginDialog`、`useDismissable` 与状态函数复用，移除组件反向导入 App |
| P2 | 等待器超时后仍占用闭包，工具包装和权限确认重复 | 清理等待器/定时器，合并工具包装；原生授权仍要求明确允许 |
| P2 | 主进程命令混在 IPC；同名模型可静默选错服务商 | 提取命令执行模块，明确拒绝歧义与未知命令，捕获当前引擎对象 |

抽象只覆盖相同语义。没有让四种引擎共享一个执行循环，也没有向 Claude Code/Codex 注入重复的桌面 web 工具。持久化顺序保证仅针对应用进程，未引入跨进程文件锁。

## 验证

- 单元与契约：`npm test`，59/59 通过；涵盖原有四引擎契约及新增应用策略、运行时、界面、服务回归。

- 构建输出和最终 `app.asar` 均通过 Electron 冒烟；NSIS 安装包已生成，ProductVersion 为 0.5.4。

真实 Claude `/compact` 的上游 502 限制沿用兼容性文档；本轮未重新进行付费原生模型压缩实测。协议/错误处理测试不能证明该上游故障已解决。
